# gaz-lab-app — офлайн-шпаргалка по ГОСТ для газовых измерений

Приложение для Android/браузера: пошаговый маршрут методики с привязкой к ГОСТ,
автоматическими расчётами и блокировками, которые не дают закрыть шаг с неполными
или противоречивыми данными.

Работает **полностью офлайн**. Сеть не используется ни для чего.

---

## 1. Актуальность данных — читать в первую очередь

| Параметр | Значение |
|---|---|
| Дата сверки карты стандартов | **04.10.2026** |
| Онлайн-проверка ФГИС Росстандарта | **НЕ выполнялась** |
| Онлайн-проверка приложения Росаккредитации | **НЕ выполнялась** |
| Онлайн-проверка реестра ПНД Ф | **НЕ выполнялась** |

Приложение показывает в шапке метку **«актуальность не подтверждена после 04.10.2026»**
и не даёт снять её, пока пользователь не сверит стандарты вручную и не нажмёт
«Отметить как сверено вручную» на вкладке «Стандарты».

Что было подтверждено реальным источником: паспорт аспиратора **ПУ-4Э**
(производитель, ximko.ru, 04.10.2026) и перечень каналов газоанализаторов серии
ПОЛАР по открытым каталогам производителя. Остальное — из профессиональных знаний,
номера пунктов ГОСТ проставлены **по смыслу разделов**.

Перед каждым выездом сверяйте: ФГИС Росстандарта (gostassistent.ru / allgost.ru) —
статус и редакция ГОСТ; приложение Росаккредитации — область аккредитации; реестр
Росприроднадзора — действующие ПНД Ф.

## 2. Запуск и установка на Android

**Как локально проверить (на ПК):**

```powershell
cd D:\работа\gaz-lab-app
# любой статический сервер, например:
python -m http.server 8080
# или из PowerShell без Python:
$job = Start-Job { Set-Location "D:\работа\gaz-lab-app"; (New-Object Net.HttpListener).Prefixes.Add("http://localhost:8080/"); }
```

Проще всего: открыть `index.html` напрямую в браузере — приложение работает и с
`file://`, данные лежат в `data/data.js` и не требуют `fetch`.

**Установка как приложение на телефон:**

1. положить папку на любой статический хостинг (или открыть `index.html` с телефона);
2. в Chrome на Android: меню → «Установить приложение» / «На экран „Домой“»;
3. после установки приложение запускается офлайн через service worker.

Никаких аккаунтов, серверов и разрешений на сеть не требуется.

## 3. Что внутри

```
gaz-lab-app/
  index.html                 приложение (UI + расчётное ядро + экспорт)
  sw.js                      service worker: cache-first, полный офлайн
  manifest.webmanifest       установка на Android
  icons/icon.svg             иконка
  icons/icon-maskable.svg    иконка с маской
  data/data.js               СБОРКА для приложения (window.GAZ_DATA)
  data/gost.json             КАНОН: карта стандартов + дата актуальности
  data/devices.json          КАНОН: карточки приборов
  data/m-A.json … m-U.json  КАНОН: методика по этапам
  README.md
```

Канонические источники — семь JSON-файлов в `data/`. `data/data.js` собирается из них
одной командой (PowerShell, без Node):

```powershell
$d='D:\работа\gaz-lab-app\data'
$g=[System.IO.File]::ReadAllText("$d\gost.json",[Text.UTF8Encoding]::new($false))|ConvertFrom-Json
$dv=[System.IO.File]::ReadAllText("$d\devices.json",[Text.UTF8Encoding]::new($false))|ConvertFrom-Json
$order=@('m-A.json','m-B.json','m-C.json','m-D.json','m-E.json','m-F.json','m-G.json','m-U.json')
$ph=@(); foreach($f in $order){$o=[System.IO.File]::ReadAllText("$d\$f",[Text.UTF8Encoding]::new($false))|ConvertFrom-Json;$ph+=@{file=$f;phase=$o.phase;steps=$o.steps}}
$all=@{generated='2026-10-04';validity=$g.dataValidity;standards=$g.standards;deviceRule=$dv.rule;devices=$dv.devices;phases=$ph}
[System.IO.File]::WriteAllText("$d\data.js","window.GAZ_DATA = $(($all|ConvertTo-Json -Depth 14 -Compress));",[Text.UTF8Encoding]::new($false))
```

Все вкладки, входные поля, расчёты, чек-листы и критерии лежат в JSON — правка
методики не требует трогать код.

## 4. Что нужно донести и заполнить

Приложение **намеренно** не подставляет приборные характеристики по памяти.
Незаполненные поля помечены «заполнить из паспорта», а шаг с таким прибором не
закрывается. Список того, что нужно внести:

### Весы (запрошено как «ХАС 220»)

Точная модель не подтверждена. В сети есть аналитические весы серии **AS 220**
(НПД 220 г, цена деления 0,1 мг) — похожее название, но это **не доказательство**.
Нужно с паспорта или свидетельства:

- [ ] полное наименование, изготовитель
- [ ] класс точности по ГОСТ Р 53291-2008
- [ ] наибольшая нагрузка и наименьшая масса
- [ ] цена деления / дискретность индикации, мг
- [ ] вид поверки: поверка или калибровка; в каких единицах результат
- [ ] заводской № и № свидетельства, дата поверки до
- [ ] требования к помещению (температура, вибрация)

### Гири

- [ ] класс точности (ОТ2 / ОТ1 / Е1 / Е2)
- [ ] состав набора, номиналы, индивидуальные отклонения
- [ ] свидетельство о поверке или метрологической аттестации

### Сушильный шкаф

- [ ] рабочий диапазон (нужен ≥ 105 °C с запасом)
- [ ] погрешность поддержания температуры
- [ ] неравномерность по рабочему объёму
- [ ] № свидетельства, дата

### Муфельная печь

- [ ] рабочий диапазон (нужен ≥ 400 °C с запасом)
- [ ] погрешность, № свидетельства

### ПУ-4Э

- [ ] модификация (с АКБ / без)
- [ ] фактический диапазон своего канала — серийно 0,2–2 и 2–20 л/мин, но бывает иначе
- [ ] № свидетельства, дата, **подтверждение, что поверен именно объёмный расход**
- [ ] предел таймера вашего прибора

### Микроманометр Testo 510/511/512

- [ ] **дискретность отсчёта в Па** — ключевое поле
- [ ] погрешность, диапазон, № свидетельства

### Testo 340

- [ ] предельная температура газа для установленного зонда
- [ ] фактический набор сенсоров (есть ли NO, SO2, NOx)
- [ ] погрешность по каждому каналу

### Testo 440

- [ ] предел температуры газа для вашего зонда влажности
- [ ] погрешность

### Трубка Пито

- [ ] тип и коэффициент **Kт из свидетельства о поверке** (не подставлять 1,0)

### Нулевая трубка

- [ ] фактические диаметры наконечников в комплекте, мм

### Прочее

- [ ] номер аттестата лаборатории и срок действия области
- [ ] номера ПНД Ф / ФР.1.31 по каждому компоненту
- [ ] ПДВ по каждому компоненту
- [ ] толщина стенки газохода δ (влияет на площадь дважды)

## 5. Что считает приложение автоматически

| Величина | Формула в коде |
|---|---|
| Эквивалентный диаметр, прямоугольное сечение | `Dэ = 2ab/(a+b)` (= 4A/P) после вычета `2δ` |
| Площадь сечения | `S = (a−2δ)(b−2δ)` или `πD²/4` |
| Пригодность сечения | `≥ 4·Dэ` по потоку, `≥ 1·Dэ` против потока |
| Координаты точек | центры равновеликих ячеек сетки n×n; для круга — 0,044/0,146/0,296/0,704/0,854/0,956 D |
| Плотность газа с учётом влажности | парциальные давления сухой части и пара, молярная масса пара 18,016 г/моль |
| Влагосодержание | `f = 622·φE(t)/((B−Pст)−φE(t))` |
| Скорость в точке | `vᵢ = √(2·K·Kт·Pотсч / ρг)` |
| Пригодность микроманометра | дискретность ≤ 1/10 расчётного ΔP при 4 м/с |
| Погрешность скорости | `u(v)/v = ½·u(ΔP)/ΔP`, где `u(ΔP) = √((рез/√12)² + (кл·ΔP/100)²)` |
| Изокинетический расход | `Q = v·πd²/4` + отклонение от допуска |
| Время отбора | `V₀ = m_тр/Z`, сравнение с пределом таймера |
| Запылённость | `Z [мг/м³] = Δm [г]·10⁶ / V₀ [л]`, где `V₀ = V·(B−Pст)/1013,3·273/(273+t)` |
| Массовый выброс пыли | `M [г/с] = Z·Vн.у./1000`, `Mгод [т/год] = M·3600·T/10⁶` |
| Концентрация при н.у. | `Cн.у. = C·(B−Pст)/1013,3·273/(273+t)` |
| Выброс ЗВ | `M [г/с] = Cн.у.·Vн.у./1000` |
| Бюджеты неопределённости | скорость, расход, запылённость, газа; проверка «u прибора ≤ 1/3 метода» |

**Единицы давления — главный источник ошибки в этой области.** Нормальное давление:
`1013,3 гПа` = `101,325 кПа` = `760 мм рт.ст.`. Делитель в формуле приведения зависит
от единицы, в которой ведётся `B`:

| `B` в | делитель | ошибка при неверном выборе |
|---|---|---|
| **гПа** (в приложении) | **1013,3** | деление на 101,3 → результат занижен в 10 раз |
| кПа | 101,3 | — |
| мм рт.ст. | 760 | — |

Ровно эту ошибку я нашёл в работе Алисы (подстановка `B ≈ 1013` вместо `101,3`
при давлении в гПа) и в первом варианте собственного кода. В приложении единица
зафиксирована в шапке расчётного ядра одной константой, чтобы это нельзя было
развести в разных шагах.

Все объёмы — в **литрах** или кубометрах явно, массы — в **граммах**.
В приложение вносится объём пробы **при рабочих условиях**; приведение выполняется
программой — так исключена двойная нормировка.

## 6. Ограничения (честно)

- Приложение **не заменяет чтение текста ГОСТ** и не является нормативным документом.
- Номера пунктов ГОСТ проставлены по смыслу разделов и требуют сверки.
- Проверка пригодности микроманометра опирается на «правило 1/10» из п. 6.4.3 —
  это общее требование, а не дословная формулировка вашей методики.
- Порог привеса 10 мг задан как поле метода и **по умолчанию не подставляется**.
- Допуск изокинетичности ±5 % — тоже поле, не константа.
- Расчётные формулы реализованы и проверены на эталонных примерах вручную
  (см. проверку ниже), но автоматических тестов в среде нет — Node и Python
  в этой машине отсутствуют.

### Ручная проверка расчётов (сверено независимым пересчётом)

Эталон: сечение 2,5 × 3,0 м, δ = 5 мм, B = 1013,3 гПа, Pст = −3 гПа, tг = 180 °C,
v = 6 м/с, ρ₀(сухой) = 1,293 кг/м³.

```
внутр. размеры      a = 2,490 м   b = 2,990 м        (вычтено 2δ = 10 мм)
Dэ                  = 2·2,490·2,990 / 5,480          = 2,717 м
требуемое по потоку = 4 · Dэ                        = 10,87 м   имеется 0,6 м → нарушение в 18 раз
S                   = 2,490 · 2,990                 = 7,445 м²  (а не 7,500)
коэфф. приведения    = 1016,3/1013,3 · 273,15/453,15 = 0,6046
ρг (сухой)          = 1,293 · 1,0030 · 0,6027       = 0,7817 кг/м³
ΔP при 4 м/с        = ½ · 0,7817 · 16               = 6,25 Па    → при дискретности 10 Па всего 0,6 отсчёта
Q раб. усл.         = 6 · 7,445                     = 44,67 м³/с
Qн.у.               = 44,67 · 0,6046                = 27,01 м³/с
Δm = 12 мг, V = 210 л → V₀ = 210 · 0,6046          = 126,96 л
Z                   = 0,012 · 10⁶ / 126,96          = 94,52 мг/м³
M пыли              = 94,52 · 27,01 / 1000          = 2,553 г/с
Mгод при 8760 ч      = 2,553 · 3600 · 8760 / 10⁶    = 80,5 т/год
```

Контрольная прикидка для газа: при `Z = 20 мг/м³` и `Qн.у. = 27 м³/с` выброс пыли
составляет `0,54 г/с` ≈ `17 т/год`. Если расчёт даёт величину на порядки другую —
искать ошибку в множителях и в единицах давления.

**Что было поймано при собственной проверке кода** (и почему проверка обязательна):
`Dэ = 4ab/(a+b)²` вместо `2ab/(a+b)` — занижение в 2,7 раза; делитель `101,3` вместо
`1013,3` при давлении в гПа — занижение в 10 раз; неопределённость отсчёта считалась
через произвольный коэффициент 2,35 вместо `рез/√12`; в расчёте площади обращалась
к несуществующей переменной. Все четыре исправлены, расчётное ядро отделено от данных.

## 7. Развитие

Текущая реализация — PWA, потому что её можно проверить и поставить на телефон
прямо сейчас, без Android SDK. Расчётное ядро из `index.html` переносится
в Kotlin/Compose без изменения структуры данных: JSON-файлы `data/` становятся

Для переноса потребуется Android SDK и Gradle — в этой среде их нет.

```powershell
Invoke-Expression ([IO.File]::ReadAllText(
  'D:\работа\gaz-lab-app\tools\build-variant2.ps1',[Text.UTF8Encoding]::new($false)))
```

Сборщик не запускает Excel — книга пишется прямой генерацией OOXML в ZIP,
поэтому выполняется за доли секунды и не может подвесить систему.

**Почему так:** попытка проверить книгу через COM (`New-Object -ComObject Excel.Application`)
оставила висящий `EXCEL.EXE` и подвесила сессию на несколько минут. Проверка
в Excel поэтому заменена офлайн-валидацией `tools\verify-offline.ps1`:
согласованность стилей, адресов ячеек, ссылок на листы, наличие
`fullCalcOnLoad` и отсутствие незаполненных склеек в формулах.

**Чего офлайн-проверка не доказывает:** что Excel открывает файл без
предупреждений о восстановлении. Это единственное, что стоит проверить при
первом открытии — открыть файл и убедиться, что жёлтые ячейки пустые, а
зелёные показывают числа, а не ошибки.

## Почему Excel удалял формулы («Удаленные записи: Формула»)

Класс ошибок, который стоит знать про генерацию `.xlsx` напрямую.

Excel молча удаляет любую формулу, которую не может разобрать, и сообщает об
этом в журнале восстановления. Причина была в самом генераторе: фрагменты
формул вида

```powershell
(cN ("=IF($G$" + $jrw + '="","",$G$' + $jrw + ')'))
(cN ("='Газовый анализ'!$G$" + $A3['R_CO']))
```

записаны в **двойных** кавычках PowerShell. Внутри `$G`, `$B`, `$A`, `$C`, `$D`
— имена переменных PowerShell, они разворачиваются в пустоту, и в книгу
попадало `=IF($32="","",$32)` или `='Газовый анализ'!$25` — ссылка без буквы
столбца, которой не существует.

Правило, которое теперь зафиксировано в сборщике:

- формула пишется **только в одинарных** кавычках PowerShell;
- имя листа в формуле Excel требует апострофов, а апостроф закрывает строку
  PowerShell → такие ссылки собираются **только функциями** `X1`, `X2`, `X3`,
  `S2r`, `X3c`, а не литералом в коде;
- `$bad` в `build-variant2.ps1` останавливает сборку, если в исходниках снова
  появился фрагмент формулы в двойных кавычках;
- `verify-offline.ps1` проверяет каждую формулу: ссылка без буквы столбца,
  ссылка на несуществующий лист, ссылка за пределы листа, нечётное число кавычек.

Тот же класс ошибок я поймал трижды подряд: в генераторе, в скрипте замены и
в самом валидаторе. Проверка, которая ловит ошибку, должна быть написана в том
же языке, что и код, — иначе она наследует ту же ошибку.

## Исправления, найденные при собственной проверке

Их было пять, и все — того же класса, что и ошибки в работе Алисы:

1. `Dэ = 4ab/(a+b)²` вместо `2ab/(a+b)` — занижение в 2,7 раза.
2. Делитель `101,3` вместо `1013,3` при давлении в гПа — занижение в 10 раз.
3. `f = 622·φE/(B−φE)` подписано как г/м³, а эта формула даёт г/кг сухого
   воздуха. Правильно: `f = 0,79328·pв`, где `pв = φ/100·E` гПа.
4. Формула Магнуса для давления насыщенного пара неприменима выше ~99 °C:
   при 180 °C она даёт 11138 гПа вместо 9974 гПа и «перегружает» газ.
   Заменена кусочно: Магнус до 99 °C, выше уравнение Антуана.
5. `pв` умножалось на φ (в процентах) без деления на 100 — ошибка в 100 раз.

Все пять найдены **не** чтением кода, а пересчётом эталонного примера
независимо от формул. Проверочный пример и его результаты — в разделе 6.
